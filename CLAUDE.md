# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

See also `AGENTS.md` for persona/boundary conventions (conventional commits are required — the release agent parses them for SemVer bumps).

## Commands

```bash
go build ./...                       # build
go test ./...                        # all tests
go test -race -v ./...               # what CI runs
go test ./pkg/dahua -run TestParseEvent   # single test
go vet ./...                         # static analysis
go mod tidy -diff                    # CI fails if go.mod/go.sum are untidy
gofmt -l .                           # CI fails if this prints anything
go run .                             # run locally (needs env vars, see below)
go run . -healthcheck                # probe the local /health endpoint, exit 0/1
go run . -capture 2m                 # record the camera's raw event stream to a file (camera env only)
bash scripts/release-agent-test.sh   # release-agent + release-notes + shipped-path checks (CI runs it)
docker build -t dahua-companion .
```

CI (`.github/workflows/ci.yml`) runs: `scripts/check-go-version.sh`, `scripts/release-agent-test.sh`, `go mod verify`, `go mod tidy -diff`, build, vet, golangci-lint (v2, config in `.golangci.yml` — std-error-handling exclusion preset), a `gofmt -l` check, then `go test -race`. `security.yml` runs `govulncheck ./...` on push/PR and weekly (a failure outside a PR opens — or comments on — an issue labeled `security-scan`), plus `dependency-review` on PRs; `codeql.yml` runs CodeQL on push/PR and weekly (do not also enable CodeQL "default setup" in repo settings — they conflict). `docker-publish.yml` also runs on PRs as a **build-only** validation — every step guards on `github.event_name != 'pull_request'`, so nothing is pushed or signed; it exists to catch a broken `Dockerfile` or action bump before a release. CI-style workflows cancel superseded runs via `concurrency`; `docker-publish.yml` deliberately has no concurrency group so an in-flight publish is never cancelled.

Lint locally with the same version CI uses:

```bash
docker run --rm -v "$PWD":/app -w /app golangci/golangci-lint:v2.15.0 golangci-lint run ./...
```

`go` is **not installed** in the WSL dev environment, but `docker` is. To run the CI checks locally, use the official image (`-buildvcs=false` avoids a git-ownership error on the bind mount, and `-race` needs the non-alpine image for cgo; the named volume keeps the module cache warm between runs):

```bash
docker run --rm -v "$PWD":/app -w /app -v dahua-gomodcache:/go/pkg/mod \
  -e GOFLAGS=-buildvcs=false golang:1.27.3 \
  sh -c 'go build ./... && go vet ./... && gofmt -l . && go test -race ./...'
```

## Configuration

`config.Load()` (and `config.LoadCamera()`, the camera-only subset `-capture` uses) calls `godotenv.Load(".env.local")` then `godotenv.Load(".env")`. godotenv never overwrites an already-set variable, so **`.env.local` wins over `.env`, and real environment variables win over both**. `.env.example` is committed; `.env` and `.env.local` are gitignored — copy the example and fill in real values.

Camera transport: `DAHUA_SCHEME` (`http` default, or `https`), with `DAHUA_CA_FILE` (PEM roots, typically the camera's self-signed cert) or `DAHUA_TLS_INSECURE=true`; `dahua.New` builds the TLS config (so it returns an error for an unusable CA file) and every camera URL goes through `Client.url`.

Required (`envconfig`, fatal if missing): `MQTT_BROKER_URL`, `MQTT_CLIENT_ID`, `MQTT_USERNAME`, `MQTT_PASSWORD`, `HOSTNAME_OR_IP`, `DAHUA_USERNAME`, `DAHUA_PASSWORD`. Optional: `MQTT_TOPIC` (default `doorbell/pressed`), `MQTT_AVAILABILITY_TOPIC` (default `doorbell/availability`), `MQTT_HUMAN_TOPIC` (default `doorbell/human`; set explicitly empty to disable human detection — envconfig only applies a default when the variable is unset), `MQTT_DISCOVERY_PREFIX` (empty = HA discovery disabled; `homeassistant` matches HA's default), `MQTT_PAYLOAD_FORMAT` (`empty` default, or `json` = `{"event_type","timestamp","channel"}`; anything else is fatal), `HUMAN_COOLDOWN` (default `10s`, `0` disables), `SNAPSHOT` (comma list of `press`/`human`; `human` with human detection disabled is fatal), `SNAPSHOT_SOURCE` (`request` default, or `event`; see Snapshot sources below), `LOG_LEVEL` (default `info`; read directly by `logger.Init`, like `APP_ENV`), `HEALTH_PORT` (default `8080`), `APP_ENV=development` for human-readable console logging instead of JSON.

`MQTT_USERNAME`, `MQTT_PASSWORD`, `DAHUA_USERNAME` and `DAHUA_PASSWORD` also accept `<NAME>_FILE` (Docker secrets); `loadSecretFiles` copies the file into the variable before `envconfig` runs, a directly set variable wins, and a trailing newline is stripped.

The camera credentials are deliberately prefixed `DAHUA_` — bare `USERNAME`/`PASSWORD` collide with variables the surrounding environment may already export, and real env vars beat `.env` files. `config.Load()` still honors the legacy bare names as a deprecated fallback (warned at startup, new names win when both are set); the fallback is slated for removal in a future release.

## Architecture

Single Go binary. `main.go` wires the pieces with a signal-cancelled `context.Context` and waits on a `WaitGroup` for shutdown:

```
dahua.Listen ──onEvent()──> mqtt.PublishPress/PublishHuman ──press & detection queues──> mqtt.ProcessQueue ──> broker
     └─(SNAPSHOT)─> snapshot.Snapshotter ─or─ dahua.ListenSnapshots ──> mqtt.PublishSnapshot ──────────────> broker
health.Server (:HEALTH_PORT) serves /health and /metrics
```

- **`pkg/dahua`** — split by concern: `dahua.go` (client, TLS, `Probe`), `stream.go` (the shared long-poll runner, watchdog, reconnect loop), `events.go` (event types, `parseEvent`, cooldown, reporting), `ivs.go` (IVS data-block parser), `snapshot.go` (`snapshot.cgi` fetch), `snapstream.go` (event-snapshot stream), `capture.go` (raw recording for `-capture`). Opens a long-poll HTTP GET to `/cgi-bin/eventManager.cgi?action=attach&codes=[AlarmLocal]&heartbeat=5` (plus `SmartMotionHuman,CrossLineDetection,CrossRegionDetection` when `Client.DetectHumans` is set, which `main.go` derives from a non-empty `MQTT_HUMAN_TOPIC`) using digest auth (`icholy/digest` transport), built with `http.NewRequestWithContext` so cancelling the context aborts the stream immediately. Every connection runs under an **idle watchdog** (`streamIdleTimeout` = 3 missed heartbeats = 15s): any bytes from the camera reset it (raw reads, not parsed lines — heartbeat framing doesn't matter), and silence tears the stream down for reconnect, since OS TCP keepalives would otherwise leave a dead stream — and `IsConnected()==true` — undetected for minutes. The watchdog is armed before `Do`, so it also bounds connect + digest handshake. Scans the response line-by-line (scanner buffer raised to `maxLineBytes` = 1 MB: an over-long line is otherwise a fatal scan error the reconnect loop would hit forever); `parseEvent` parses `Code=...;action=...;` lines and only reports `AlarmLocal` (`DoorbellPressed`) or `SmartMotionHuman` (`HumanDetected`) with `action=Start` (or absent action). `onEvent` receives a `dahua.Event{Kind, Channel}` (channel = the line's `index`); `main.go` maps the kind to `PublishPress`/`PublishHuman`. Human detections within `HumanCooldown` of the last *reported* one are suppressed (suppressed ones don't extend the window). IVS tripwire/intrusion events carry a JSON `data={...}` block, usually spread over the following lines: `startIVS`/`ivsBlock` collect it until its braces balance (capped at 64 KB; a `--` boundary line abandons it) and report `HumanDetected` when `Object.ObjectType` or any `Objects[].ObjectType` is `Human` (case-insensitive), for `Start` or `Pulse` actions in any case — the API docs show both. Detections from SMD and IVS share the cooldown, so a camera reporting both for one person yields one event. These IVS formats are from the API PDFs, not yet confirmed against a real doorbell. Every other non-framing line (other codes, `Stop`s, multi-line `data={...}` blocks) is logged at debug level by `logUnhandledLine` — the raw material for supporting new camera models. `Listen` wraps `listen` in `backoff/v7` retry (via `retryStream`, shared with the snapshot stream) with `MaxElapsedTime(0)` (retry until cancelled) and `MaxInterval` lowered to 10s; the backoff **resets once a connection is established**, so only consecutive failures grow the reconnect delay. `Probe` is the read-only authenticated camera check (`magicBox.cgi?action=getMachineName`) that health uses; the shared `http.Client` intentionally has no client-wide timeout (the stream is endless), so bounded calls pass a context deadline.
- **`pkg/mqtt`** — `New()` connects with paho `ConnectRetry` enabled (a down broker at boot no longer kills the process), the reconnect ceiling lowered to 30s, and keepalive lowered to 10s (+5s ping timeout) so a half-open broker socket stops reporting `IsConnectionOpen` within seconds, not paho's default ~40s. `PublishPress`/`PublishHuman` are non-blocking sends onto **separate** buffered channels of 100 (full queue = drop the new event), so detections can never crowd out a press; `ProcessQueue` checks the press queue alone before selecting on both, so presses always jump the line (shutdown drain does presses first too). The payload is built at enqueue time: empty, or JSON per `MQTT_PAYLOAD_FORMAT` (with JSON, discovery omits `value_template` since the payload already carries `event_type`). `ProcessQueue` delivers; while the broker is unreachable it holds the current event and polls once a second, and any event older than 30s (`maxEventAge`) is **dropped, not delivered late** — stale doorbell events are worthless by design. QoS 1 (the PUBACK turns a dead-socket publish into a logged drop instead of silence) bounded by `publishTimeout` = 5s, no app-level retry on failure (no duplicate presses), not retained. The success log carries `latency_ms` (queue-entry → broker ack). **Availability** is retained `online`/`offline` on `MQTT_AVAILABILITY_TOPIC`: a Last Will covers process death, `OnConnect` re-announces the stored state after every reconnect, `Disconnect` leaves an explicit `offline` (a clean disconnect suppresses the will) and waits up to `drainTimeout` for its ack before disconnecting (paho's quiesce doesn't wait for in-flight QoS 1, which used to cut the retained `offline` off), and `main.go` wires `dahua.Client.OnConnectionChange` to `PublishAvailability` so the topic mirrors the event stream — availability publishes are serialized under a mutex so the retained value converges to the latest state. When `MQTT_DISCOVERY_PREFIX` is set, `OnConnect` also publishes a retained **HA MQTT discovery** config (`<prefix>/event/<sanitized-client-id>/doorbell/config`, an `event` entity with `device_class: doorbell` whose `value_template` supplies the event JSON since the press payload is empty; plus `.../human/config`, a `device_class: motion` event entity, when human detection is enabled). On shutdown `ProcessQueue` **drains**: already-queued fresh events get a best-effort flush bounded by `drainTimeout` = 2s, never waiting for a reconnect; and while holding an event, `deliver` wakes on an `OnConnect` signal instead of only the 1s poll.
- **Snapshot sources** — `SNAPSHOT_SOURCE=request` (default) uses `pkg/snapshot` below; `SNAPSHOT_SOURCE=event` instead runs `dahua.Client.ListenSnapshots`, a second long-lived stream (`snapManager.cgi?action=attachFileProc&Flags[0]=Event&Events=[...]`) parsed with `mime/multipart`: a `text/plain` part of `Events[0].EventBaseInfo.Code/Action/Index` lines, then an `image/jpeg` part with the camera's still from the moment of the event (heartbeat parts between them are skipped). It shares `stream`/`retryStream` (watchdog + backoff) with the event stream via `track=false` (never touches `IsConnected`), applies its own copy of the human cooldown, and publishes synchronously through `mqtt.PublishSnapshot`, so memory stays at one image. Its state is `Client.SnapshotStreamConnected` and the `dahua_companion_snapshot_stream_*` metrics (deliberately not `/health` or availability: snapshots are best effort). Its format is from the API PDF, unconfirmed on a real doorbell.
- **`pkg/snapshot`** — `Snapshotter` fetches a camera still after an event (`dahua.Client.Snapshot`: `snapshot.cgi?channel=<index+1>`, capped at 5 MB) and hands it to `mqtt.PublishSnapshot`, which publishes to `<event topic>/snapshot`, QoS 1, **not retained, never queued** (broker down = dropped). At most one fetch runs at a time, bounded by a 5s timeout: a request while one is in flight is skipped, except a press cancels and replaces an in-flight detection fetch (a generation counter keeps the cancelled goroutine from clearing its successor's state). `main.go` calls `Request` right after queuing the event, so the still lands after it in practice (ordering is best-effort, not enforced), and `Wait`s on it before `mqttClient.Disconnect`. Discovery adds `image` entities ("Last ring"/"Last person") for the enabled snapshots.
- **`pkg/metrics`** — hand-rolled, dependency-free Prometheus text exposition (counters, duration summaries, scrape-time gauge funcs) served at `/metrics` on the health server via `health.Server.Handle`. The app's metrics are package-level vars in `metrics.go` (event label `press`/`human`); `dahua`, `mqtt` and `snapshot` increment them directly, `main.go` registers the two connection gauges. Deliberately not the Prometheus client library: a dozen counters don't justify its module tree in a scratch image.
- **`pkg/health`** — own `ServeMux` (not the default mux), `ReadHeaderTimeout`, listen port from `HEALTH_PORT`. `/health` writes the status code *before* the body and returns 503 unless MQTT is connected, the event stream is connected, and a `Probe` bounded to 5s succeeds. A successful probe is cached for `probeCacheTTL` = 60s (failures never are; probes are serialized so concurrent requests share one). It takes two injected `func() bool`s and the probe func from `main.go` and imports neither `dahua` nor `mqtt`.
- Connection state lives on the clients as `IsConnected()` methods (`atomic.Bool` on dahua, paho's `IsConnectionOpen()` on mqtt) — there are no package-level flags.
- **`pkg/logger`** — zerolog global logger with caller info; Unix timestamps in production, `ConsoleWriter` when `APP_ENV=development`; global level from `LOG_LEVEL` (default `info`).
- `main -capture <duration>` (`capture.go`) records the camera's raw event stream — subscribed to **every** code (`codes=[All]`), byte for byte — to `capture-<UTC stamp>-events.txt` in `-capture-dir`, then prints the event codes seen; `-capture-snapshots` adds the event-snapshot stream (doorway pictures, so opt-in). It loads only `config.LoadCamera()`, no MQTT. Its output is what to ask a user for when their camera's events differ from the API PDFs, and real recordings make good test fixtures.
- `main -healthcheck` probes the local `/health` endpoint and exits 0/1. It backs the Docker `HEALTHCHECK` (scratch has no shell or curl) and deliberately reads only `HEALTH_PORT`, not the full config.
- `main_test.go` is an end-to-end smoke test: it boots the real `main()` against an embedded `mochi-mqtt` broker (test-only dependency) and a fake camera, asserting press and human-detection delivery (JSON payloads), snapshots, availability, discovery, `/health`, and SIGTERM shutdown. It is the only test allowed to call `main()` (the `-healthcheck` flag registration is once-only), and it trims `os.Args` first so `main`'s `flag.Parse` doesn't see `go test`'s flags.

## Release flow

`release-agent.yml` runs `scripts/release-agent.sh` weekly (Mondays 09:00 UTC) or on dispatch. Proposals are **gated on shipped paths** (`SHIPPED_PATHS`: `main.go`, `capture.go`, `pkg/`, `go.mod`, `go.sum`, `Dockerfile`, `.dockerignore`): CI/docs/devcontainer-only churn never proposes, and bump detection + the changelog read only commits touching those paths, so a CI-only `feat` cannot inflate the bump. Chore-only shipped changes **accumulate for 21 days** (`CHORE_MAX_AGE_DAYS`) before proposing; `feat`/`fix`/breaking propose immediately, and a manual dispatch sets `FORCE_PROPOSAL=true` to skip the wait. The bump follows Conventional Commits (a `!` marker after the type/scope or a `BREAKING CHANGE` footer → major, `feat` → minor, otherwise patch — detected from `--format=%s`/`%B`, since `--oneline`'s hash prefix defeats subject anchors). The issue labeled `release-agent` is opened, or updated **only when the proposal content actually changed** — an ignored proposal does not re-notify weekly. `scripts/release-agent-test.sh` (run in CI) exercises every gate branch in scratch repos, tests `release-notes.sh`, and fails if a top-level Go source file is missing from `.dockerignore` or either `SHIPPED_PATHS`. The proposal's Changes section and the GitHub release body both come from `scripts/release-notes.sh <prev-tag> <ref> [version]`: shipped commits grouped by Conventional Commit type (breaking, features, fixes, performance, dependencies, other) with commit links, plus a `docker pull` line and compare link (`release-publish.yml` falls back to the issue text only if the script fails, and needs `fetch-depth: 0` for it). The proposal records the HEAD SHA it was generated from (`**Commit:**` line). Adding the `release-approved` label triggers `release-publish.yml`, which tags **that recorded commit** (not main's tip — commits landing after review don't ship), cuts the GitHub release, calls `docker-publish.yml` to build, push, and cosign-sign the image, then verifies the version manifest actually exists on ghcr before closing the issue; any failure comments on the issue with the run link. Issue title/body reach the workflow shell via `env:` — never template `${{ github.event.issue.* }}` into a `run:` script; the body carries commit text.

Images carry SLSA provenance (`mode=max`) and SBOM attestations on the index, and are tagged `vX.Y.Z` + `latest` (linux/amd64 + linux/arm64) on every publish path: the approval flow above (`workflow_call` — the tag it creates comes from `GITHUB_TOKEN`, which GitHub never lets trigger other workflows, hence the explicit call), a hand-pushed `v*.*.*` tag (image only — no GitHub release), or Actions → Docker → Run workflow with a version to re-publish an existing tag (the recovery knob for a release whose docker leg failed, like v0.1.2/v0.1.3 — and v0.2.0's cache-service failure; note this path does not close the proposal issue, only the label-triggered flow does).

## Docker

Multi-stage: a `golang:<ver>-alpine` builder → `scratch`, `CGO_ENABLED=0`, `-trimpath -ldflags="-s -w"`, running as non-root `scratchuser` (only `/etc/passwd` is copied over). The CA bundle is copied from the builder, so an MQTT broker over TLS (`ssl://`) verifies. The `HEALTHCHECK` runs `/app/main -healthcheck` since scratch has no shell.

**The Go version is declared in three places** and must stay consistent — `toolchain` in `go.mod`, the `golang:<ver>-alpine` builder in `Dockerfile`, and the `devcontainers/go:<major>-<go-minor>-bookworm` image in `.devcontainer/devcontainer.json`. Renovate sees three unrelated dependencies, so `renovate.json` groups them into one "go version" PR (patch releases split off into an auto-merged "go patch" PR, since they are usually the govulncheck fix; `gomodTidy` keeps Renovate's `go.sum` tidy), and `scripts/check-go-version.sh` fails CI if they drift regardless of how the drift happened. Run it directly after touching any of the three:

```bash
./scripts/check-go-version.sh
```

Note the dev container tag is `<image-definition-major>-<go-minor>-<debian>`; the `1-` definition family stopped at Go 1.24, so current Go requires the `2-` family.

`.dockerignore` is an allow-list (`*` then `!/main.go`, `!/capture.go`, `!/go.mod`, `!/go.sum`, `!/pkg/`). A new top-level source file or directory is invisible to the build until it is added there — and to the release scripts' `SHIPPED_PATHS`; `release-agent-test.sh` catches a missed top-level `.go` file.

## Reference

Dahua HTTP API PDFs live in `documentation/`; the app subscribes to `AlarmLocal` (doorbell press) and, with human detection on, `SmartMotionHuman`, `CrossLineDetection` and `CrossRegionDetection` (the IVS rules count only when their data names a `Human`). The IVS and snapshot-stream formats come from these PDFs and are unconfirmed on a real doorbell — a `-capture` recording from one is the way to confirm or correct them.
